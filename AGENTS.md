# Project

**Smart City — Платформа «Идеи для региона» (область Абай)**

Платформа, через которую любой житель области Абай подаёт идею или предложение по развитию города (в т.ч. проблему, например яму на дороге — с фото и точкой на карте), а государственные органы получают, классифицируют и обрабатывают эти предложения с прозрачными статусами.

Проект делается как учебный хакатон, но с прицелом на реальное внедрение — стараемся не городить одноразовый прототип.

## Repositories

- **Backend**: [RollSatrs/SmartBackend](https://github.com/RollSatrs/SmartBackend) — NestJS + Drizzle ORM + PostgreSQL. REST API, авторизация, хранение идей/статусов/категорий, AI-классификация идей. Общий бэкенд для мобильного приложения и сайта.
- **Mobile (текущий приоритет)**: [RollSatrs/SmartMobile](https://github.com/RollSatrs/SmartMobile) — React Native/Expo. Основной клиент для защиты хакатона: кабинет жителя, форма подачи идеи с картой, кабинет госоргана.
- **Frontend / сайт (на паузе)**: [RollSatrs/SmartFrontend](https://github.com/RollSatrs/SmartFrontend) — Next.js + shadcn/ui. Тот же функционал, что и в мобильном приложении, но как веб-версия. Issues заведены и ждут — приоритет ниже мобильного, разработка возобновится, когда подключится Влад.

## Product context

- **Целевой пользователь на старте**: любой житель области Абай, без строгой верификации на этапе MVP.
- **Роли**: Житель (Resident), Государственный орган (GovOfficial), опционально Admin.
- **Форма идеи**: название, описание проблемы/решения, категория, точка на карте (с автоопределением района/нас. пункта), фото.
- **AI-классификация**: автоматическое определение категории и направления по тексту и фото при создании идеи — заменяет ручной выбор направления и служит критерию «автоматизация» на защите хакатона.
- **Статусы идеи**: получена → на рассмотрении → в работе → завершена / отклонена / нужны уточнения.

## Collaboration

- GitHub Issues — источник правды по задачам. Не полагаемся на историю чата.
- Общий GitHub Project "Smart City" отражает статус задач по всем трём репозиториям (когда будет создан).
- Разработка — в отдельных ветках: `agent/<developer>/<issue-number>-<short-name>`.
- Готовая работа оформляется через Pull Request со ссылкой `Closes #<issue-number>`.
- Изменения, затрагивающие несколько репозиториев (например, контракт API между backend и mobile/frontend), фиксируются и обсуждаются в Issue или PR-комментариях — не только в личном чате.
- Перед началом работы над Issue: проверить, что он открыт, не взят другим агентом/разработчиком, и посмотреть связанные/блокирующие задачи.
